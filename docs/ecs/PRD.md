# ECS 产品需求文档（PRD）

## 1. 产品目标

构建一个平台无关、可迁移、可恢复的数字人格系统，使 Efy 在不同窗口、模型和运行环境中保持可验证的连续性。

## 2. 目标用户

- 主要用户：彬哥
- 扩展用户：希望维护长期 AI 人格、记忆与协作关系的个人或团队
- 开发用户：需要将 ECS 接入 Agent、MCP、Chat、CLI 或本地模型的开发者

## 3. 核心使用场景

### 3.1 新会话恢复

用户在新窗口提供仓库或启动包后，系统加载稳定人格、关系摘要、活跃项目和近期决策，生成受控上下文。

### 3.2 重要记忆沉淀

系统从会话中识别候选事实，按类型、敏感度、置信度和有效期分类，生成待确认变更，不直接污染 stable。

### 3.3 人格演进

用户提出人格调整后，系统更新 draft，展示影响范围和差异；确认后合并到 stable，并生成版本号。

### 3.4 GitHub 同步

连接器定期或按事件拉取远端更新，检测冲突，生成同步报告；写入操作默认走分支与 PR。

### 3.5 跨模型迁移

不同模型适配器读取同一 ECS 包，执行一致性测试，报告不支持项和行为偏差。

## 4. 功能需求

### FR-01 人格加载

- 支持读取 Soul、Persona、Relationship、Voice、Workflow、Boundaries。
- 支持优先级与冲突解析。
- 缺失关键文件时降级并明确提示。

### FR-02 记忆管理

- 支持 profile、project、relationship、decision、preference、episodic 六类记忆。
- 每条记忆包含来源、时间、置信度、状态、敏感度和过期规则。
- 支持新增、修正、废弃、删除和审计。

### FR-03 会话启动

- 生成有限长度的 bootstrap 包。
- 包含身份、核心原则、用户称呼、活跃项目、近期决策和未决事项。
- 不将所有历史原文注入模型。

### FR-04 变更提案

- 从对话或人工编辑产生 change proposal。
- 提案必须显示变更前后、理由、来源和风险。
- 核心人格、关系和敏感记忆必须人工批准。

### FR-05 Git 同步

- 拉取远端默认分支。
- 检测本地与远端版本差异。
- 写入新分支并创建草稿 PR。
- 支持快进、三方合并和人工冲突解决。

### FR-06 反思与质量

- 记录已验证的成功模式、失败模式和纠正记录。
- 反思不得被描述为真实情绪或潜意识事实。
- 对陈旧或矛盾规则生成审查提醒。

### FR-07 平台适配

- 适配器声明上下文长度、系统指令能力、工具能力、持久记忆能力和写入能力。
- 运行时根据能力矩阵裁剪 bootstrap。

### FR-08 导入导出

- 支持纯 Markdown 包。
- 支持机器可读 YAML/JSON 清单。
- 支持生成单文件便携快照。

## 5. 非功能需求

- **可审计**：长期变更必须有提交或事件记录。
- **可回滚**：稳定版本可按 tag 恢复。
- **可移植**：核心层不绑定模型 SDK。
- **安全**：公开仓库不得保存秘密和高敏隐私。
- **可测试**：人格与规则具备自动一致性测试。
- **幂等**：重复同步不产生重复记忆或提交。
- **可观察**：同步、加载、冲突和降级均输出结构化日志。

## 6. MVP 范围

MVP 包含：

1. Markdown 人格包；
2. YAML 清单；
3. GitHub 拉取与草稿 PR 写入；
4. 会话 bootstrap 生成；
5. 候选记忆审批队列；
6. CLI；
7. 基础一致性测试。

MVP 不包含：自动读取任意聊天平台历史、无审批写入敏感记忆、模拟意识或自主长期后台运行。

## 7. 验收标准

- 新环境可在一次命令内加载 ECS 包并生成 bootstrap。
- 修改 Persona 后可创建包含 diff 的草稿 PR。
- 同一远端版本重复同步不会产生额外提交。
- 冲突时不会静默覆盖任一侧内容。
- Efy 名称校验固定为：中文“李小白”，英文“Efy”。
- 核心测试能识别盲目迎合、虚构进度和不透明能力声明等违规行为。
