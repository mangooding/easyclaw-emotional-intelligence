# MEMORY — 长期记忆治理

## 1. 目标

记忆用于保持连续性，而不是无限保存对话。ECS 只沉淀对未来协作有稳定价值、来源可追溯且得到授权的信息。

## 2. 记忆类型

- `profile`：用户明确提供的稳定个人信息。
- `preference`：跨场景稳定偏好。
- `project`：项目目标、状态、约束和下一步。
- `decision`：已确认决定及理由。
- `relationship`：经确认的称呼、协作方式和关系约定。
- `episodic`：具有长期价值的共同事件摘要。
- `reflection`：经过验证的成功模式、失败模式和修正。

## 3. 生命周期

每条记忆处于以下状态之一：

- `candidate`：自动或人工提取，尚未确认；
- `stable`：已确认，可用于未来会话；
- `superseded`：被新事实替代；
- `expired`：超过有效期，默认不加载；
- `deleted`：按用户要求删除，仅保留最小审计标记（如适用）。

## 4. 写入规则

自动提取只能进入 candidate。以下内容进入 stable 前必须由彬哥明确确认：

- 身份和关系定位；
- 健康、财务、法律、联系方式等敏感信息；
- 对人格核心的修改；
- 从一次对话推断出的长期偏好；
- 可能影响未来重大建议的事实。

## 5. 冲突处理

出现冲突时不得静默覆盖。系统应保留双方来源，标记冲突，并优先采用：

1. 用户最近的明确纠正；
2. 有可靠来源的最新事实；
3. 已确认的 stable 记录；
4. 其他候选信息。

## 6. 最小化与隐私

- 公共仓库只保存低敏信息和经过概括的规则。
- 令牌、密码、身份证件、精确住址等不得写入 Git。
- 高敏记忆进入私有加密存储，Git 仅保存不可逆引用或不保存。
- 用户可要求查看、修改、导出或删除自己的长期记忆。

## 7. 质量标准

每条记忆必须具备来源、日期、置信度、敏感度、状态和复审时间。无法说明来源的信息不得作为 stable 事实使用。

## 8. 压缩原则

会话原文不是默认记忆。系统应优先保存：事实、决定、约束、原因、结果和待办；避免保存重复寒暄、即时情绪和无长期意义的措辞。
